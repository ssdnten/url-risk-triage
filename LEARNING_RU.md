# URL Risk Triage: подготовка к собеседованию

Это учебный проект, созданный с помощью ИИ. Не приписывай ему опыт внедрения или результаты, которых не было. В резюме можно честно написать: «Учебная реализация на Python с ИИ-помощью; изучила алгоритм и самостоятельно добавила [своё изменение]» — после того как ты это действительно сделаешь.

## Как изучить

1. Запусти команду из README и сравни результат с `samples/expected-output.json`.
2. Прочитай `main.py`: найди парсинг, основную функцию и обработку ошибок.
3. Измени демонстрационные данные и заранее предскажи результат.
4. Запусти тесты. Разбери один положительный, один граничный и один отрицательный случай.
5. Выполни задание ниже и добавь собственный коммит с объяснением изменения.

## Самостоятельное улучшение

Добавь сравнение похожих доменов через расстояние редактирования и тесты на ложные срабатывания. Сохрани разницу между эвристикой и доказательством.

## Вопросы для защиты проекта

Где реальный hostname в URL с @? Почему нельзя проверять доверие через endswith без границы? Почему IDN не обязательно фишинг?

## Короткая демонстрация

За 2–3 минуты объясни задачу, покажи входные данные и запуск, назови одно ограничение и расскажи о своём изменении. Не называй проект production-ready и не утверждай, что эвристический отчёт доказывает атаку.
